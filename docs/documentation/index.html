Core concepts

A short tour of the ideas that recur throughout the API. Each maps to a module in the core library.

Generation

The core library builds valid pacs.008 FI-to-FI Customer Credit Transfer messages across the supported version range (001.01 through 001.13). You supply party, agent and amount data; the generator emits schema-conformant XML pinned to the version and scheme you target.

Validation layers

Validation runs in layers so failures surface early and specifically: first a JSON Schema check on the structured input, then an IBAN checksum verification on account identifiers, and finally an XSD check of the serialised message against the official ISO 20022 schema. A message must pass every layer to be considered clean.

Scheme profiles

A message can be schema-valid yet wrong for its rail. Dedicated profiles encode the rules each market enforces for CBPR+, HVPS+, Fedwire, CHAPS, T2 RTGS and SCT Inst — covering usage guidelines, tracking requirements, cardinality and timing.

Structured postal address

Party addresses are modelled with PostalAddress27, supporting fully structured and hybrid forms. This is the mechanism for meeting the structured-address requirements that take effect in November 2026, when unstructured addresses begin to be rejected in key payment messages.

Security

XML is parsed with defusedxml to defend against XXE (XML external entity) attacks, file access is constrained by path-traversal allow-listing, and PII is masked in structured JSON logs to align with GDPR and PCI DSS expectations.

MCP tools

The pacs008-mcp package exposes fifteen Model Context Protocol tools over stdio, backed by the core library. They cover get, validate and generate-style operations, so MCP-capable clients such as Claude, Cursor and Zed can read and edit pacs.008 messages safely, span by span.

See the pacs008-mcp README on GitHub for the full tool list and client configuration.
