# 디자인 파트너

## 아직 사례 연구가 없습니다

의도적입니다. 이 프로젝트는 입증할 수 없는 주장을 걷어내는 데 상당한 공을 들였고, 고객 사례를 지어내면 그 노력이 무의미해집니다. 이곳에 사례가 실릴 때는 해당 조직의 동의를 받아 이름을 밝히고 실제로 있었던 일을 서술할 것입니다.

pacs008을 검토 중이고 추천인이 필요하시면 말씀해 주십시오. 있는지 없는지 솔직히 알려드리겠습니다.

## 디자인 파트너란

ISO 20022 지급 메시지를 도입 중이며, 실제 요구사항에 맞춰 시험하고 이 도구의 부족한 점을 알려줄 의향이 있는 조직입니다. 대개 은행, 지급결제 서비스 제공자, 기업 자금 부서 또는 지급 소프트웨어 공급업체입니다.

## 저희가 요청하는 것

- 예제만이 아니라 귀사의 메시지 프로파일로 pacs008을 실행해 보십시오.
- 어떤 스킴 규칙이 부족한지, 마감일이 언제인지 알려주십시오.
- 결함은 재현 가능한 수준으로 정확히 알려주십시오. 메시지 유형, 프로파일, 시행일, 기대한 결과를 함께 적어주십시오.
- 공개된 규칙이 틀렸다면 알려주십시오. 규칙 수정이 기능보다 우선합니다.

지급 데이터는 요청하지 않습니다. 모든 것은 합성 레코드로 재현할 수 있으며, 운영 데이터는 보내지 않으시는 편을 선호합니다.

## 얻으시는 것

- 다음에 어떤 스킴 규칙을 어떤 순서로 구현할지에 대한 직접적인 영향력.
- 공개 전 규칙 집합 변경 사전 고지. 동작 변화가 귀사의 처리 흐름을 놀라게 하지 않도록 합니다.
- 귀사의 규칙과 테스트 파일을 인증 집합에 추가. 향후 릴리스가 조용히 망가뜨리지 못하게 합니다.
- 원하시면 기여 표기, 원하지 않으시면 표기 없음.

## 제공할 수 없는 것

- 지원 계약이나 가용성 보장. 소수의 관리자가 운영하는 오픈소스 프로젝트입니다.
- 인증. 검증 통과 결과가 거래 상대방이나 스킴 운영자가 그 메시지를 수용하리라는 보장은 아닙니다.
- 이메일로 보내신 내용의 기밀 취급. 민감한 사안은 보안 신고 경로를 이용해 주십시오.
