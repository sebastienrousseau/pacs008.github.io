# 設計夥伴

## 此處尚無案例研究

這是刻意如此。本專案花了很大力氣剔除無法證實的說法，編造客戶故事只會讓這份努力付諸東流。日後此處出現案例研究時，將在對方許可下寫明組織名稱，並陳述真實發生的事。

若您正在評估 pacs008 並需要推薦人，請告訴我們——有沒有，我們都會據實以告。

## 什麼是設計夥伴

正在導入 ISO 20022 支付訊息、願意對照真實需求進行測試並指出本工具不足之處的組織。通常是銀行、支付服務提供商、企業資金部門或支付軟體供應商。

## 我們的請求

- 請以貴方自己的訊息設定檔執行 pacs008，而不只是範例。
- 請告知您缺少哪些方案規則，以及您的截止期限。
- 請以可重現的精確度回報缺陷：訊息類型、設定檔、生效日期以及您預期的結果。
- 若已發布的規則有誤，請告知我們。規則更正優先於新功能。

我們不索取支付資料。一切都可用合成紀錄重現，我們更希望您絕不向我們傳送正式環境資料。

## 您能獲得什麼

- 對下一步實作哪些方案規則及其順序的直接影響力。
- 規則集變更在發布前的預先告知，使行為變化不會讓您的流程措手不及。
- 將貴方的規則與測試檔案納入認證集合，使日後版本無法悄然破壞它們。
- 若您願意可署名，不願意則不署。

## 我們無法提供的

- 支援合約或可用性保證。這是一個維護者寥寥的開源專案。
- 認證。驗證通過並不保證任何交易對手或方案營運方會接受該訊息。
- 對您來信內容的保密處理。敏感事項請走安全通報管道。
