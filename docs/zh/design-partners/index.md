# 设计伙伴

## 此处尚无案例研究

这是有意为之。本项目花了很大力气剔除无法证实的说法，编造客户故事只会让这份努力付诸东流。日后此处出现案例研究时，将在对方许可下写明组织名称，并陈述真实发生的事。

若您正在评估 pacs008 并需要推荐人，请告诉我们——有没有，我们都会如实相告。

## 什么是设计伙伴

正在实施 ISO 20022 支付报文、愿意对照真实需求进行测试并指出本工具不足之处的组织。通常是银行、支付服务提供商、企业资金部门或支付软件供应商。

## 我们的请求

- 请用贵方自己的报文配置运行 pacs008，而不只是示例。
- 请告知您缺少哪些方案规则，以及您的截止期限。
- 请以可复现的精度报告缺陷：报文类型、配置、生效日期以及您期望的结果。
- 若已发布的规则有误，请告知我们。规则更正优先于新功能。

我们不索取支付数据。一切都可用合成记录复现，我们更希望您绝不向我们发送生产数据。

## 您能获得什么

- 对下一步实现哪些方案规则及其顺序的直接影响力。
- 规则集变更在发布前的预先告知，使行为变化不会让您的流程措手不及。
- 将贵方的规则与测试文件纳入认证集合，使日后版本无法悄然破坏它们。
- 若您愿意可署名，不愿意则不署。

## 我们无法提供的

- 支持合同或可用性保证。这是一个维护者寥寥的开源项目。
- 认证。校验通过并不保证任何交易对手或方案运营方会接受该报文。
- 对您来信内容的保密处理。敏感事项请走安全报告渠道。
